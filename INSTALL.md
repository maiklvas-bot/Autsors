# DNS · Внешний персонал — установка на своём сервере

## Что в комплекте

Dockerfile собирает приложение из исходников. Docker Compose запускает приложение и Caddy для автоматического HTTPS. База SQLite, история и аватарки хранятся в постоянном томе `app_data`. Сервер проверяет необходимость напоминаний раз в минуту. УМ и сотрудник получают сообщения только после привязки Telegram.

Это самостоятельная установка с новой базой. Данные из размещённого на Sites приложения автоматически сюда не копируются. Подключение того же токена бота переключает доставку Telegram на новый домен: одновременно один бот работает только с одним адресом.

## Требования

Linux-сервер с Docker Engine, Docker Compose plugin и openssl. Рекомендуется 2 ГБ памяти для сборки. Домен должен указывать A-записью на сервер; если есть AAAA-запись, IPv6 также должен работать. Откройте входящие TCP 80 и 443. Приложение не публикует порт базы или свой внутренний порт 3000.

## Установка

Распакуйте архив, перейдите в папку проекта и выполните:

```bash
bash install.sh
```

Установщик запросит домен без `https://`, email первого администратора, PIN дважды и токен Telegram. PIN и токен вводятся скрыто. Файл `.env` содержит секреты и доступен только владельцу файла; не публикуйте его. PIN хранится в базе в виде хеша, в `.env` его нет.

После сборки откройте `https://ваш-домен`, войдите с заданными email и PIN. В «Настройках» задайте графики магазинов. В «Доступах» создайте управляющих и назначьте им филиалы. В личном кабинете проверьте подключение Telegram, задайте отдельный одноразовый код и перейдите в бота. Дождитесь приветствия с вашим именем. Веб-PIN и одноразовый код Telegram — разные данные.

## Проверка установки

```bash
docker compose ps
docker compose logs --tail=100 app
docker compose logs --tail=100 proxy
```

Состояние `healthy` подтверждает запуск сервера, но не регистрацию бота. При успешной регистрации в журнале приложения появляется `Telegram webhook configured`. Если домен или HTTPS ещё не готовы, следующий запрос к приложению повторит подключение. Страница «Telegram-бот» показывает результат отдельной проверки Telegram.

Назначьте тестовому сотруднику смену, проверьте получение уведомления в течение минуты. Сотрудник нажимает «Начать смену», затем «Сдать отчёт». Управляющий подтверждает часы после окончания смены. Подтверждённые часы должны появиться в табеле и выгрузке Excel.

## Обновление и сохранность данных

```bash
docker compose up -d --build
```

Обновление сохраняет тома. Не используйте `docker compose down -v`: эта команда удаляет базу, историю и аватарки. Перед обновлением сделайте резервную копию тома `app_data` при остановленном приложении; сохраните вместе с ней `.env`. Переносите полный том, включая SQLite-файлы, а не только `app.sqlite` из работающего сервера.

Восстановление PIN существующего администратора с доступом к серверу:

```bash
bash deploy/reset-admin.sh
```

Сброс записывается в историю и завершает старые сеансы. На своём сервере восстановление через ChatGPT не используется. Создание дополнительных администраторов выполняется из интерфейса приложения.

## Что проверено перед передачей

38 автоматических проверок: вход, смена PIN, права, область видимости УМ, сохранение истории, смены через полночь, пересечения, отчёты, подтверждение часов, графики филиалов, Excel с листами по месяцам и графиками, одноразовые коды, обработка Telegram. Отдельно запущен самостоятельный Node-сервер: проверены вход, сохранение сеанса после перезапуска и отказ при подделке платформенной личности.

Docker-движок в среде подготовки отсутствовал: сборка образа и выдача HTTPS-сертификата на вашем домене здесь не выполнялись. Фактическую доставку Telegram нужно отличать от тестирования обработчика с имитацией API. Результат подключения действующего сайта описывается отдельно в сообщении о публикации.

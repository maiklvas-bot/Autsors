# Безопасность

Не публикуйте в Issues токены, PIN, коды привязки, cookie, персональные данные или копии базы. Сообщите об уязвимости владельцу репозитория по согласованному закрытому каналу; при доступности используйте GitHub Private vulnerability reporting.

## Модель защиты

- Сервер проверяет сеанс, роль и доступные филиалы; интерфейс не является границей доступа.
- PIN хешируется scrypt, сеансы хранятся в виде хешей; cookie HttpOnly, Secure, SameSite=Lax.
- Временный PIN требует замены. Смена или сброс PIN завершает старые сеансы.
- Есть ограничения частоты входа, проверка Origin и размера запросов.
- Одноразовые коды Telegram хранятся хешированными, имеют срок действия; webhook проверяет отдельный секрет.
- Docker-приложение доступно через Caddy; заголовки платформенной личности от внешнего клиента удаляются.

## Эксплуатация

Храните .env и резервные копии вне Git с ограниченным доступом. При раскрытии токена перевыпустите его через BotFather и обновите серверную конфигурацию. Не открывайте внутренний порт приложения напрямую. Регулярно обновляйте зависимости и создавайте резервную копию полного тома при остановленном приложении. Подробности восстановления — INSTALL.md.

Автоматические тесты не заменяют независимый аудит безопасности.

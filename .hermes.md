# Hermes project context — Autsors

Этот файл — корневой project context для Hermes. Перед любой работой сначала прочитай все применимые `AGENTS.md` и `CLAUDE.md` (а также `AGENT.md`, если он есть) и соблюдай их. Если их указания конфликтуют с этим файлом, для Hermes приоритетен этот `.hermes.md`. Существующие instruction-файлы не изменяй.

## Проект

- Repo: `Autsors`
- Default branch: `main`
- Canonical `project_id`: `autsors`
- Notification route: по заданному registry mapping маршрут не зарегистрирован. Fail closed; явно отметить `notification route: registration required`; не отправлять lifecycle/Telegram delivery, не придумывать topic, credentials или chat ID. Регистрацию выполнять только отдельным разрешённым процессом через внешний canonical CX Forge registry по `project_id=autsors`.

## Обязательные правила

- Пользовательский язык — русский; английский допустим только в коде, командах, путях, идентификаторах и точных логах.
- Economy route: GPT-5.6 Luna через ChatGPT/Codex OAuth.
- Codex выполняет implementation, tests и focused fixes.
- Claude Code использовать только для architecture, difficult debugging или одного независимого review.
- Результат Claude принимать только если фактический `modelUsage` точно совпадает с запрошенной моделью. При недоступности Codex/Claude явно сообщить ограничение; silent fallback запрещён.
- Fable запрещён. Astra запрещена для cron, monitoring, polling, Telegram, status, formatting, subagents и production coding.
- Один writer на worktree. Не выполнять commit, push, PR, merge, release, deploy, изменение secrets или destructive actions без явного разрешения пользователя.
- WSL использовать только для Linux-specific tests. Docker запускать только после обнаружения и проверки доступности.
- Не объявлять CI green без проверок именно текущего commit; незакоммиченные изменения не считать частью commit.
- Test/build/check commands брать только из прочитанных `AGENTS.md`/`CLAUDE.md` и manifest-файлов; не выдумывать команды.

## Lifecycle, delivery и секреты

- Lifecycle events и Telegram destination получать из внешнего canonical CX Forge registry; локальные значения не заменяют registry.
- Delivery считать подтверждённой только при наличии provider message ID. `delivery_unknown` автоматически не переотправлять.
- Секреты загружать только через profile-scoped Hermes secret loading.
- Не помещать в Git state DB, logs, transcripts, credentials, tokens или chat IDs.

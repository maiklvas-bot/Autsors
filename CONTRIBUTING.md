# Изменения проекта

Право вносить изменения определяется LICENSE и разрешением владельца. Основная ветка защищается процессом подтверждения владельца проекта.

1. Создайте изменения локально в `develop` или в отдельной ветке `feature/*` от неё. Прямые коммиты в `main` запрещены.
2. Делите работу на законченные этапы и сохраняйте каждый этап отдельным локальным коммитом.
3. Не отправляйте новые коммиты в GitHub до явного подтверждения владельца после завершения и проверки этапа.
4. После подтверждения отправьте рабочую ветку и откройте Pull Request в `main`. Слияние и публикация требуют отдельного разрешения владельца.
5. Сохраните серверную проверку ролей и филиалов. Не доверяйте данным клиента.
6. Добавляйте новые SQL-миграции; не редактируйте уже применённые миграции.
7. Для исправлений авторизации, хранения и расчётов добавьте тест, воспроизводящий ошибку.
8. Выполните `npm ci` и `npm test` на Linux с Node.js 24.
9. При слиянии обновите версию и CHANGELOG, если меняется поведение.

Не включайте .env, реальные данные, cookie и токены. Комментарии в коде должны объяснять причины нетривиального решения. В PR укажите результат проверок и оставшиеся ограничения. Подробный порядок действий ИИ-агента закреплён в `AGENTS.md`.

# Изменения проекта

Право вносить изменения определяется LICENSE и разрешением владельца.

1. Создайте отдельную ветку и опишите проблему в Pull Request.
2. Сохраните серверную проверку ролей и филиалов. Не доверяйте данным клиента.
3. Добавляйте новые SQL-миграции; не редактируйте уже применённые миграции.
4. Для исправлений авторизации, хранения и расчётов добавьте тест, воспроизводящий ошибку.
5. Выполните `npm ci` и `npm test` на Linux с Node.js 24.
6. Обновите документацию и CHANGELOG, если меняется поведение.

Не включайте .env, реальные данные, cookie и токены. Комментарии в коде должны объяснять причины нетривиального решения. В PR укажите результат проверок и оставшиеся ограничения.

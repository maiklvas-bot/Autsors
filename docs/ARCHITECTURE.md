# Архитектура

- `app/`: React/Vinext, страницы, API и серверные проверки.
- `app/lib/model.ts`: правила смен, сотрудников, ролей и истории.
- `app/lib/auth.ts`: PIN, сеансы и границы доступа.
- `app/lib/telegram.ts`: диалоги бота и уведомления.
- `app/lib/excel.ts`: экспорт с шаблоном OOXML.
- `drizzle/`: SQL-миграции и схема.
- `worker/index.ts`: Worker entrypoint, используется также самостоятельным сервером.
- `deploy/`: Node HTTP-сервер, адаптер SQLite/файлов, создание администратора, Caddy.
- `tests/`: проверки правил, хранилища, авторизации, экспорта и runtime.

## Режимы размещения

Sites использует D1 и R2. Docker запускает тот же собранный Worker через Node.js с адаптером SQLite и файловым хранилищем. Caddy обслуживает HTTPS. Состояние, история и изображения сохраняются в томе app_data. Изменения записываются с проверкой версии состояния, конфликт требует повторного чтения.

Webhook Telegram принимает только запросы с серверным секретом. Регистрация выполняется при включённом TELEGRAM_AUTO_CONNECT и заданном PUBLIC_ORIGIN. Самостоятельный сервер раз в минуту вызывает защищённую обработку напоминаний; при остановке сервера планировщик не работает.

Перенос между Sites и Docker не реализован автоматически. Миграции схемы не являются переносом рабочей базы между этими средами.
